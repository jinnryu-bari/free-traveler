## (이전) 미검증 사유 — 로그인 후 실제 저장, 참고용

`MateComposerForm`이 로그인 사용자에게 Form을 보여주고 `POST /api/mates`로 저장을 시도하는 코드는 작성·커밋했지만, **실제 이메일 로그인(매직 링크) 흐름은 제가 자동화할 방법이 없어 끝까지 실행해보지 못했습니다.** 대신 다음까지만 확인했습니다:

- 비로그인 상태에서 정확히 로그인 CTA만 뜨고 Form 자체가 렌더되지 않음(`E2E-005` 통과)
- `POST /api/mates`가 비로그인 요청을 401로 차단하는 것은 W05에서 이미 실제 DB로 확인됨
- 로그인 후 화면(Form 필드, 성공/실패 처리)은 코드 리뷰 수준으로만 확인, 브라우저에서 실제 로그인해보지 않으면 눈으로 확인 불가

**확인 결과(2026-09-18):** 사용자가 브라우저에서 항공편·숙소 입력/요약/외부 이동과 동행 구하기 비로그인 안내·Tip 3개를 확인해 W08 Checkpoint를 승인했습니다. `/account`는 W11~W12 미구현으로 현재 404이므로, 로그인 후 실제 `mate_posts` 저장 검증은 이 시점에 수행할 수 없습니다 — **W12(`PAGE-SCR005` 포함) 완료 후 수행할 항목으로 이월**합니다. 외부 이동 링크는 `external_links` 테이블이 아직 비어 있어(seed 미적용) 기본 URL(Google Flights/Hotels)로 열립니다 — 관리자 URL 설정 기능은 W12에서 구현됩니다.

## 설계 메모(참고)

- **동행 스타일/태그**: `mate_posts` 테이블(`DB-SCHEMA-BASE`, 이미 완료된 Task)에 별도 컬럼이 없어, 스키마를 바꾸지 않고 설명 앞에 `[여행 스타일: ...]` 한 줄로 합쳐 저장합니다. 수업 실습 프로젝트 성격상(`CLAUDE.md` 규칙 24) 스키마 변경 없이 기존 컬럼으로 처리했습니다.
