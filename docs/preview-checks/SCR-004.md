## 브라우저 확인 중 발견 → 수정한 버그 (커밋 `a4b65c6`)

사용자가 실제 브라우저로 `/mates`를 확인하는 중, **동행글이 0개일 때 왼쪽 Empty State가 아주 좁게 찌그러져 표시되는 문제**를 발견해 보고했다.

- **원인**: `PAGE-SCR004`(`page.tsx`)가 `ListGrid`+`DetailPanel`을 `mx-auto max-w-[1240px] ... lg:flex lg:gap-6 lg:px-10` 행으로 감싸는데, `ListGrid` 자신도 W09에서 이미 동일한 `mx-auto max-w-[1240px] px-5 py-10 lg:flex lg:gap-6 lg:px-10` `<section>`으로 스스로를 한 번 더 감싸고 있었다. 그 결과 `ListGrid` 내부의 `lg:w-[40%]` 컬럼이 "진짜 1240px 행의 40%"가 아니라 "이미 줄어든 자기 자신의 content box의 40%"로 계산되면서 극도로 좁아졌다 — 카드가 있을 때는 카드 내용 때문에 덜 티가 났지만, Empty State는 짧은 텍스트/버튼뿐이라 찌그러짐이 눈에 띄게 드러났다.
- **수정**: `ListGrid`의 중복 `<section>` 래퍼를 제거하고(`w-full lg:w-[40%]`만 남은 순수 콘텐츠 블록으로 변경), Page Owner가 제공하는 바깥 행 하나만 남겼다.
- **추가 요청 반영**: 글이 0개이고 선택도 없을 때 `DetailPanel`의 "왼쪽 목록에서 동행글을 선택하면..." Placeholder를 완전히 숨기고(`return null`), 그만큼 `ListGrid`가 행 전체 너비(100%)를 넘겨받도록 했다. 둘 다 같은 `fetchFilteredMatePosts` 함수로 독립적으로 같은 필터를 조회해 판정하므로 결과가 항상 일치한다.
- **확인 방법**: Chrome 확장이 이번에도 연결되지 않아, `scratchpad`에 임시 Playwright 스크립트(파일로 남기지 않음)를 작성해 Desktop(1280px)·Mobile(390px) 두 폭에서 Empty State 컨테이너와 버튼 2개의 실제 bounding box를 측정했다.
  - Desktop: Empty State 컨테이너 1160px 폭(행 전체), "필터 초기화"/"동행글 작성하기" 버튼이 가로로 나란히, 각각 126px/156px — 찌그러짐 없음.
  - Mobile: 컨테이너 350px 폭(화면 전체), 버튼 2개가 세로로 쌓이고 각각 284px(거의 전체 폭) — 찌그러짐 없음.
  - 두 폭 모두 "왼쪽 목록에서 동행글을 선택하면..." Placeholder 개수 0 — 정상적으로 숨겨짐.
