## 남은 제약 / 수동 확인 필요

- **Gallery 실패 상태의 자동 E2E 검증을 완료하지 못했습니다.** 구현(`9057686`)은 `destination-grids.tsx`와 동일한 검증된 DOM 조작 패턴을 그대로 따르고, `npm run build`/lint/typecheck는 전부 통과했으며, 실제 8개 이미지는 정상 로딩됩니다(육안 확인·URL 전수 200 확인). 다만 "이미지 로딩 실패 시 대체 안내가 뜨는지"를 Playwright로 강제 재현하는 자동 테스트는 만들지 못했습니다 — 시도 중 이 세션에서 오늘 새로 추가한 Client Component는(관련 없는 최소 테스트 버튼 포함) Playwright 테스트 브라우저에서 클릭·에러 이벤트 자체가 발동하지 않는 현상을 발견했고(`.next` 캐시 삭제 후 재빌드해도 동일), 반면 이전에 이미 커밋된 Component(예: 여행지 카드)는 같은 브라우저에서 정상 동작했습니다. 이는 구현 결함이라기보다 이 자동화 테스트 샌드박스 특유의 제약으로 보이나, 확정하지 못했습니다.
  - **요청:** 브라우저 DevTools의 Network 탭에서 Gallery 사진 URL 중 하나를 차단(block request)하거나 오프라인으로 전환한 뒤, 그 칸이 (a) 같은 크기를 유지한 채 "사진을 불러오지 못했어요" 안내로 바뀌는지, (b) 다른 칸들이 밀리거나 빈 공간이 생기지 않는지 직접 확인해 주시면 감사하겠습니다.
- `MANUAL-CONTENT-REVIEW`, `MANUAL-PERF-LIGHTHOUSE`, `MANUAL-RESPONSIVE-VISUAL`, `MANUAL-EXTERNAL-LINKS`(각 Component의 Verify 열) — 자동 검사가 아니므로 사람이 별도로 수행해야 합니다.
