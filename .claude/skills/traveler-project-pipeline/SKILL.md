# Traveler Project Pipeline

Turns the locked design/route contract for Free Traveler into an executable, auditable task pipeline under `TASKS/`. This skill does not write application code — it produces `TASKS/00_TASK_LIST.md`, one Markdown detail file per task under `TASKS/TASK-<ID>.md`, and (via the audit step) `TASKS/TASK_MANIFEST.csv` + `TASKS/TASK_AUDIT_REPORT.md`.

**Common principle across every command in this pipeline:**
1. Always use this skill (`traveler-project-pipeline`) — load it before doing anything else in any of the three commands.
2. Always read the actual files (via Read/Glob/Grep on disk) — never paraphrase from memory or from an earlier turn in the conversation. Inputs can drift between sessions.
3. Never write application/implementation code, `src/**` component code, API route code, or SQL migrations from this pipeline. This pipeline only produces Task List / Task detail / audit-report **definition documents**.
4. Never ignore a Task Audit failure. `scripts/audit_tasks.py` exiting non-zero means the pipeline run is not complete — report every failure and either fix the Task List/detail files or ask the user, but do not declare success.

## Canonical inputs (read-only, never edit during this pipeline)

| File | Role |
|---|---|
| `design-reference/SCREEN_ROUTE_CONTRACT.json` | **Screen list source of truth.** `schema_version` must be `traveler-screen-route-v1`. |
| `design-reference/UI_CONTRACT.md` | Section order, components, states, navigation, Desktop/Mobile rules, prohibited features per Screen. |
| `design-reference/D-001/DESIGN.md` | Design tokens, Section rhythm, Hero rule, Empty State rule (LOCKED — never change while generating tasks). |
| `docs/06_SRS_UIUX_REVISED.md` | Route inventory revision, Use Case → Screen mapping (Route/Screen structure only — REQ-FUNC/REQ-NF content itself stays in Baseline SRS `02_SRS_BASELINE.md.md`). |
| `docs/PROJECT_SCOPE.md` | **Requirement classification source of truth** — IMPLEMENT vs EXCLUDED and implementation method per requirement (REQ-FUNC-001~080, REQ-NF-001~034). |
| `package.json` | Confirms stack: Next.js App Router, TypeScript, Tailwind CSS. Test runner (Vitest/Playwright) is added by a Task, not assumed present. |
| `src/app/**`, `src/components/**`, `src/lib/**`, `src/data/**` (actual file tree, checked live via Glob, not from memory) | Determines which `Expected Files` in a Task are "create" vs "extend". |
| `docs/ARCHITECTURE.md`, `docs/DECISION_LOG.md` | System-boundary and decision context — read when a Task's scope is ambiguous. |

`HARNESS_SCHEMA = "traveler-screen-route-v1"`. Both `scripts/validate_inputs.py` and `scripts/audit_tasks.py` assert `SCREEN_ROUTE_CONTRACT.json.schema_version == HARNESS_SCHEMA` and fail loudly if it drifts.

## Pipeline order

1. `/gen-tasklist` → runs `scripts/validate_inputs.py` first; refuses to write/update `TASKS/00_TASK_LIST.md` if validation fails.
2. `/gen-task-details` → writes one detail file per Task row in `TASKS/00_TASK_LIST.md` at `TASKS/TASK-<ID>.md`.
3. `/audit-tasks` → runs `scripts/audit_tasks.py` (**must** run after step 2). Fix and re-run until it exits 0 (`AUDIT_PASS`).

Never skip straight to `/gen-task-details` without a `TASKS/00_TASK_LIST.md` that already covers the Task in question — details are generated *from* the Task List, not invented independently. If `TASKS/00_TASK_LIST.md` already exists (it does, as of 2026-09-16 — 76 tasks), `/gen-tasklist` re-runs in **update mode**: it reconciles the existing table against the canonical inputs rather than blindly overwriting decisions already recorded there (see that command file for the exact procedure).

## Task file layout

```
TASKS/00_TASK_LIST.md          # canonical, human-readable Task List (§2 tables + §4 EXCLUDED table)
TASKS/TASK-<ID>.md             # one detail file per Task, 1:1 with 00_TASK_LIST.md §2 rows
TASKS/TASK_MANIFEST.csv        # generated by scripts/audit_tasks.py — flat CSV render of the Task List
TASKS/TASK_AUDIT_REPORT.md     # generated by scripts/audit_tasks.py — 18-check audit result
```

There is no `.claude/tasks/` directory in this pipeline — an earlier iteration used `.claude/tasks/tasklist.json` + `.claude/tasks/details/*.md`; that layout is retired. Do not create files there.

### `TASKS/00_TASK_LIST.md` §2 row schema (16 columns, pipe-table)

`Seq · Task ID · 제목 · Category · Implementation Status · Requirement Ref · Screen · Route · Page Entry · Depends On · Expected Files · Functional AC · Visual AC · Security/Privacy AC · Verify · Priority`

- **Requirement Ref** may use `~` ranges and prefix-sharing comma chains, e.g. `REQ-FUNC-001~010,068,069` or `REQ-FUNC-011~018; REQ-NF-017`. `scripts/audit_tasks.py` expands these with a regex — keep this exact format, don't invent a new notation.
- **Depends On** / **Expected Files** / **Verify** cells use `;`-separated Task IDs or file paths; `없음` means empty.
- Every row must have all 16 cells present — a row with a cell silently omitted (this has happened before with the 5 `PAGE_OWNER` rows' Expected Files cell) breaks the table alignment for every cell after the gap. Count cells when adding or editing a row.

### §4 NON_IMPLEMENTATION (EXCLUDED) table

A second table, `| Requirement | 근거(PROJECT_SCOPE.md) | 후속 방향 |`, listing every `EXCLUDED` requirement id (currently 25) with its `docs/PROJECT_SCOPE.md` rationale and a follow-up note. Requirement ids here get **no** Task row and **no** `TASKS/TASK-<ID>.md` file.

## Category → Task ID naming convention

| Prefix | Category |
|---|---|
| `PAGE-SCR00N` | `PAGE_OWNER` |
| `C-SCR00N-<slug>` | `COMPONENT` (Screen-scoped) |
| `C-GLOBAL-<slug>` | `COMPONENT` (shared: Header/Footer/Toast/SEO helper/error boundaries/policy pages) |
| `DATA-<slug>` | `DATA` (writes to `src/data/`) |
| `DB-<slug>` | `DB` (Supabase schema/RLS/access-layer/seed) |
| `API-<slug>` | `API` (`src/app/api/**/route.ts`, `src/app/auth/callback/route.ts`) |
| `UNIT-<slug>` | `UNIT_TEST` (Vitest) |
| `TEST-<slug>` | `INTEGRATION_TEST` (e.g. RLS integration test) |
| `E2E-<slug>` | `E2E_TEST` — always Chromium-only smoke |
| `MANUAL-<slug>` | `MANUAL_CHECK` — no code file, self-attested checklist |
| `RELEASE-<slug>` | `RELEASE_CHECK` — pre-merge/pre-deploy gate |

Note the id pattern is `C-SCR00N-` (no hyphen between `SCR` and the 3-digit number) — do not use the older `C-SCR-00N-` form.

## The 18 audit checks (`scripts/audit_tasks.py`, binding)

1. Task List 구현 ID와 상세 Task 파일(`TASKS/TASK-<ID>.md`) 1:1.
2. 중복 Task ID 0.
3. Depends On 누락 0 — every referenced id resolves to a real Task.
4. Dependency Cycle 0 — DFS over the `depends_on` graph.
5. Screen 5개(`SCR-001..005`) 모두 `PAGE_OWNER` Task가 정확히 1개.
6. Route·Page Entry가 `SCREEN_ROUTE_CONTRACT.json`과 일치하고, 해당 Page Owner의 detail 파일 Expected Files가 그 Page Entry를 포함.
7. Component-only Screen 0 — `COMPONENT` Task가 참조하는 Screen마다 반드시 `PAGE_OWNER` Task가 존재.
8. `PAGE-SCR001` detail 파일이 `create-next-app`/starter 제거 AC를 명시.
9. `PAGE-SCR003` detail 파일이 항공/숙소/동행 3개 탭 조립을 명시.
10. `PAGE-SCR005` detail 파일이 Guest/Member/Admin 역할별 조립을 명시.
11. `DB-SCHEMA-BASE`, `DB-RLS-BASE`, `DB-ACCESS`, `DB-SEED-BASE` Task가 전부 존재.
12. `DB-SCHEMA-BASE`가 언급하는 테이블이 6개 정식 테이블(`profiles`, `mate_posts`, `mate_applications`, `blocks`, `reports`, `external_links`) 범위를 넘지 않음.
13. 항공/숙소 관련 Task(제목에 항공/숙소/Flight/Hotel 포함 또는 REQ-FUNC-017/025/REQ-NF-017 참조)가 입력값 비저장/비전송 AC를 명시.
14. `DB-RLS-BASE`가 RLS를 언급하고, 어떤 Task든 성인확인(성인)·인증(Auth/인증) AC를 명시.
15. `E2E_TEST` Task가 1개 이상 존재하고 전부 Chromium+Smoke를 명시하며 Firefox/WebKit/시각 회귀/부하 테스트를 금지가 아닌 형태로 언급하지 않음.
16. AWS·EC2·자동(무인) Merge 관련 키워드가 어떤 Task id/제목/카테고리/화면에도 없음.
17. REQ-FUNC 80개 + REQ-NF 34개(114개) 전부가 Task Requirement Ref 또는 §4 EXCLUDED 표에 존재.
18. §4 EXCLUDED 요구사항이 어떤 Task의 Requirement Ref에도 참조되지 않음(= EXCLUDED 기능의 구현 Task/상세 파일이 생성되지 않음).

`docs/PROJECT_SCOPE.md`가 이 108(89 IMPLEMENT + ...)/114개 분류의 유일한 근거이며(검사 17/18), `scripts/audit_tasks.py`는 이를 §2/§4 테이블과 대조해 informational 행으로도 교차 확인한다. `docs/UIUX_TRACEABILITY.md`는 더 이상 이 파이프라인의 입력이 아니다(과거 버전에서 참조했으나 현재는 `docs/PROJECT_SCOPE.md`로 일원화됨).

## Task count expectation

76개 Task(§2)가 현재 기준선이다(`PAGE_OWNER` 5, `COMPONENT` 42, `DATA` 3, `DB` 4, `API` 7, `UNIT_TEST` 3, `INTEGRATION_TEST` 1, `E2E_TEST` 3, `MANUAL_CHECK` 5, `RELEASE_CHECK` 3). 이는 참고용 기준선이며, Scope가 실제로 바뀌지 않는 한 `/gen-tasklist` 재실행이 이 수를 크게 바꾸지 않아야 한다 — 크게 달라지면 `docs/PROJECT_SCOPE.md`나 `SCREEN_ROUTE_CONTRACT.json`이 먼저 바뀌었는지 확인한다.

14개 섹션, 이 순서 그대로:

```markdown

**Priority:** <P0|P1|P2>
**Seq:** <Task List의 Seq>

## Context
<1-3 sentences: 이 Task가 어떤 Screen/파이프라인 조각인지, UI_CONTRACT.md/DESIGN.md/PROJECT_SCOPE.md 근거로만>

## Project Scope
<docs/PROJECT_SCOPE.md의 구현 방식 요약과 이 Task의 Implementation Status 해설>

<표 또는 목록>

<Task id 목록, 각각 제목 병기>
```
